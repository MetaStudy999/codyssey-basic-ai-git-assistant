## 5. 한글·영어·공식 약어와 설명·재현 확인

처음 등장한 용어는 **한글명(English Full Name, 공식 약어)** 형태로 익힙니다. 별도 약어가 없는 경우 **없음**으로 표기합니다.

| 한글명 | 영어 원명 | 공식·통용 약어 | 쉬운 뜻 |
|---|---|---|---|
| **변경 비교** | Diff | 없음 | 수정 전후 내용의 차이 |
| **프롬프트** | Prompt | 없음 | AI 모델에 전달하는 작업 지시 |
| **거대 언어 모델** | Large Language Model | LLM | 언어를 처리·생성하는 모델 |
| **응용 프로그램 프로그래밍 인터페이스** | Application Programming Interface | API | 프로그램 간 요청 규칙 |

**자기 설명:** 변경 비교(Diff)는 이전 내용과 바뀐 내용을 나란히 확인하는 방법입니다. AI가 변경 설명을 제안하더라도 실제 diff와 테스트 기록으로 검토해야 합니다.

**종이 재현(실행하지 않음)**
1. 파일에서 한 줄이 수정된 사례를 가정.
2. 변경 전/후 차이를 확인한 뒤 설명 초안 작성.
3. 설명과 실제 코드가 일치하는지 검토.

**놓치기 쉬운 점:** AI가 작성한 설명은 테스트나 리뷰를 대신하지 않습니다.

**내가 이해했는지 확인:** (1) 핵심 용어의 한글·영어를 설명할 수 있는가? (2) 입력→처리→예상 결과를 자료 없이 재구성할 수 있는가? (3) 아직 실행을 검증하지 않았다는 사실을 구별할 수 있는가?

**상태:** 교육용 원리 설명·예상답만 추가했습니다. 실제 신규 코드·개발 실행·학생 L4/L5 독립 재현은 **NOT_STARTED / NOT_VERIFIED**입니다. [처음으로 돌아가기](README.md).
